Relatório Didático — Matrizes em C

Conceitos, teoria e exemplos passo a passo para resolver o exercício ex11 — Manipulação de Matrizes 1

Material de apoio para estudo. Nenhuma solução final é fornecida — apenas a explicação dos conceitos.

1. O que é uma matriz? O conceito por trás do problema

Na Matemática e na Computação, uma matriz é uma coleção de elementos do mesmo tipo (inteiros, reais, etc.) organizados em linhas e colunas. Ela é um conceito abstrato: imaginamos os dados "esticados" em uma grade, mas, na memória do computador, tudo é armazenado de forma sequencial e linear.

Quando falamos de uma matriz bidimensional de ordem m × n (lê-se "m por n"), queremos dizer:

  • m → número de linhas;
  • n → número de colunas;
  • Cada posição guarda um valor ai,j, onde i é a linha e j é a coluna.
Notação importante (vírgula dupla no problema): no texto do exercício a posição é escrita como ai,j. Isso significa o elemento que está na linha i e na coluna j. Em C, usando a convenção habitual, esse mesmo elemento é acessado como A[i-1][j-1], pois em C os índices começam em 0.

Exemplo visuol: matriz 2 × 3

a1,1a1,2a1,3
a2,1a2,2a2,3

Primeiro índice = linha, segundo = coluna.

No ex11, você vai ler duas matrizes, A e B, ambas de ordem m × n, depois aplicar uma operação indicada por um caractere ('+' ou 'x'). Para isso, os conceitos de declaração, alocação e leitura/escrita de matrizes são o alicerce.

2. Como representar uma matriz na linguagem C

A linguagem C não possui um tipo nativo "matriz". O que existe é o vetor (array), e uma matriz bidimensional nada mais é que um vetor de vetores. Existem três formas clássicas de representá-la:

2.1 Matriz estática (dimensões conhecidas em tempo de compilação)

Quando sabemos de antemão o tamanho, declaramos diretamente as dimensões. Como no ex11 os valores estão limitados a 1 ≤ m,n ≤ 10, é totalmente viável usar uma matriz estática.

#define MAX 10
int A[MAX][MAX];   // matriz estática 10x10
int B[MAX][MAX];
int C[MAX][MAX];   // guardará o resultado
Como se lê/escreve um elemento? 
int x = A[i][j];      // ler o valor na linha i, coluna j
A[i][j] = valor;      // gravar um valor

2.2 Matriz dinâmica "simulada" com um vetor unidimensional

Como a memória é linear, é possível alocar o espaço das m × n posições em um único vetor e "simular" o acesso bidimensional com aritmética de índices:

int *A = (int*) malloc(m * n * sizeof(int));
// acessar o elemento da linha i, coluna j:
A[i * n + j] = 0;    // POR QUE i*n + j ? Veja adiante.

2.3 Matriz orientada a ponteiros (vetor de ponteiros)

Nesse modelo, criamos um vetor de ponteiros, em que cada ponteiro aponta para uma "linha" alocada separadamente:

int **A = (int**) malloc(m * sizeof(int*));
for (int i = 0; i < m; i++) {
    A[i] = (int*) malloc(n * sizeof(int));
}
// acesso: A[i][j]
Qual usar no ex11? Como m,n ≤ 10, a matriz estática é a escolha mais simples e suficiente. Bastam três delas: A, B e a de resultado.

2.4 O modelo "Row-Major" e o endereço A[i*n + j]

C armazena matrizes no formato Row-Major Order: os elementos de cada linha são guardados de forma contígua (um após o outro) na memória. A linha 0 completa, depois a linha 1, e assim por diante.

Como a matriz 2×3 é guardada na memória

<end><end+1><end+2><end+3><end+4><end+5>
A[0][0]A[0][1]A[0][2]A[1][0]A[1][1]A[1][2]

Por causa disso, num vetor unidimensional de n colunas, o elemento da linha i e coluna j está na posição i*n + j: são i linhas inteiras (cada uma com n elementos) que vêm antes, mais j elementos dentro da linha.

3. Aritmética de ponteiros (o que está por trás de A[i][j])

Em C, o nome de um vetor é, na prática, um ponteiro para o primeiro elemento. Quando escrevemos A[i][j], o compilador transforma isso em aritmética de ponteiro. 

A[i][j]  é  equivalente a  *(*(A + i) + j)

// Pensando em A como um único vetor:
A[i * n + j]  é  *(A + (i*n + j))
Por que isso importa? Entender essa equivalência explica por que A[i*n + j] (matriz "achatada") e A[i][j] (matriz bidimensional) são formas de acessar o mesmo dado. No ex11, você pode usar qualquer uma delas, desde que seja consistente.

4. As operações do problema: Adição e Multiplicação

Agora vamos às duas operações que o ex11 pede. A compreensão de quando cada uma é válida é o coração do exercício — especialmente para saber quando imprimir ERROR.

4.1 Adição de matrizes (A + B)

Regra: a adição só existe quando A e B têm a mesma dimensão (mesmo número de linhas m e mesmo número de colunas n). O resultado tem a mesma dimensão e cada elemento é a soma dos elementos correspondentes:

C[i][j] = A[i][j] + B[i][j]   para todo i e j.

Exemplo do próprio ex11 (dimensão 2×3)

ABA + B
1 2 3
4 5 6		 + 6 5 4
3 2 1		 = 7 7 7
7 7 7

Cada célula é a soma das duas células na mesma linha e coluna: 1+6=7, 2+5=7, ...

Estrutura de laços (não é resposta, é o raciocínio): 
// Para cada linha i
//    Para cada coluna j
//        C[i][j] = A[i][j] + B[i][j];

Dois loops aninhados percorrem todas as m × n posições. Complexidade temporal: O(m·n).

4.2 Multiplicação de matrizes (A × B)

Regra de dimensões (o ponto crítico!): para multiplicar A × B, o número de colunas de A deve ser igual ao número de linhas de B.

Se A tem dimensão m × n e B tem dimensão n × p, então o produto existe e tem dimensão m × p.

Repare: no ex11, ambas as matrizes A e B têm a mesma dimensão m × n (definida pela entrada). Então, para a multiplicação A × B ser válida, precisamos que as colunas de A (= n) sejam iguais às linhas de B (= m). Ou seja:

A(m×n) × B(m×n) só existe se n == m (matrizes quadradas). Se m ≠ n, a multiplicação é impossível → o programa deve imprimir ERROR.

Veja por que essa é a chave dos exemplos:

  • Exemplo 2 (2×3 com 'x'): m=2, n=3 → como m ≠ n, não dá para multiplicar → ERROR.
  • Exemplo 3 (2×2 com 'x'): m=n=2 → é possível → imprime o produto 2×2.

Como o produto é definido:

coluna 0 de Bcoluna 1 de B
linha i de A A[i][0]*B[0][0] + A[i][1]*B[1][0] A[i][0]*B[0][1] + A[i][1]*B[1][1]

O produto C[i][j] é a soma dos produtos dos pares "linha i de A × coluna j de B" (produto escalar).

Fórmula do produto:
C[i][j] = Σk A[i][k] · B[k][j] 
// Raciocínio com três laços aninhados:
for (i = 0; i < m; i++)                 // linhas do resultado
    for (j = 0; j < p; j++)             // colunas do resultado
        for (k = 0; k < n; k++)         // acumula a soma
            C[i][j] += A[i][k] * B[k][j];

Complexidade temporal da multiplicação clássica: O(m·n·p). No ex11, como as duas matrizes são m×n e a condição é m==n, o produto é m×m.

Dica para quem começa no produto: antes de multiplicar, o resultado deve ser iniciado em zero. Cada posição do resultado é um acumulador (soma acumulada dos produtos). Se você esquecer de zerar, valores "lixo" da memória vão estragar o resultado.

6. (Aprofundamento) Por que a ordem dos laços importa

Como C guarda as matrizes em Row-Major (linhas contíguas), percorrer a matriz fazendo i (linha) no laço externo e j (coluna) no laço interno — acessando A[i][j] — aproveita a localidade espacial do cache: os elementos lidos estão lado a lado na memória.

Por outro lado, inverter os laços — percorrendo colunas (A[j][i]) — faz "saltos" grandes de memória a cada iteração, gerando erros de cache e tornando o programa mais lento.

Conclusão prática: nos seus laços, coloque a linha no loop de fora e a coluna no loop de dentro. Isso mantém o acesso contíguo e o código mais eficiente.

7. Como ler a entrada do ex11

Antes de calcular, é preciso interpretar corretamente o que vem da entrada padrão. A sequência é sempre esta:

  1. Ler dois inteiros: m e n (dimensões).
  2. Ler m linhas × n números → matriz A.
  3. Ler um único caractere: '+' (adição) ou 'x' (multiplicação).
  4. Ler m linhas × n números → matriz B.
  5. Decidir a operação e imprimir o resultado (ou ERROR).
Atenção ao caractere e aos espaços: o caractere da operação vem em uma linha separada. Ao usar scanf, tenha cuidado para ler a "sobra" da linha anterior (como o \n). Regras de leitura adequadas evitam que scanf "pule" o espaço de forma inesperada. Faça a leitura na ordem correta, tratando cada tipo (int para números, char para a operação).

8. Estratégia recomendada para resolver — sem dar a resposta

A seguir, uma sequência de decisões que o levam à solução. Reflita sobre cada passo e implemente por conta própria.

  1. Escolha a representação. Como m,n ≤ 10, uma matriz estática int A[MAX][MAX] (e análogas para B e resultado) resolve. Declare com constante MAX.
  2. Leia m e n. Armazene-os para usar nos loops.
  3. Leia a matriz A. Dois loops aninhados: i de 0 até m-1, j de 0 até n-1, lendo cada inteiro com scanf.
  4. Leia o caractere da operação. Guarde em char op. Pense em como reconhecer '+' e 'x'.
  5. Leia a matriz B. Mesma lógica de A.
  6. Decida pelo caractere. Use uma estrutura que ramifique (if/else ou switch) para '+' e 'x'.
  7. No caso de adição: some elemento a elemento. Sempre possível (mesmas dimensões).
  8. No caso de multiplicação: primeiro verifique a condição (colunas de A == linhas de B). Em termos de m e n, isso é m == n. Se falhar → imprima ERROR e encerre.
  9. Se a multiplicação é válida: use três loops. Lembre de zerar o resultado antes de acumular.
  10. Imprima o resultado. Percorra o resultado e imprima cada linha separando os números por espaço, com uma linha por linha da matriz (aplique a formatação que os exemplos mostram).
Dicas de verificação:
  • Confira a saída com os 4 exemplos dados: as duas somas e as duas multiplicações (incluindo o caso ERROR).
  • Teste um caso adicional seu: uma matriz 1×1 (o caso mais simples: soma e produto coincidem).
  • Confira a formatação: sem espaços extras no fim da linha, e ERROR escrito em letras maiúsculas.
